AngularJS Debugging – LabTrack Application

Using Chrome DevTools to Identify and Fix Common Errors

Application: LabTrack Lab Management System  |  Framework: AngularJS 1.8.2

Objective

To learn how to debug AngularJS applications using Chrome DevTools by identifying and fixing three common errors found in the LabTrack application:

  1. Binding Error – form input not updating the scope variable
  2. Undefined Variable – accessing a scope variable that was never initialized
  3. Controller Issue – controller name mismatch causing the app to crash

Code:

Binding Error:

In login.html, the email input field uses ng-model to bind the typed value to the AngularJS scope. A mismatch between the model name in the input and the variable name in the view caused the display to always remain blank.

Before debugging:
<!-- login.html -- Email input field --> <input type="email" ng-model="user.email" ... > <!-- The display output was referencing a DIFFERENT variable: --> <p> <strong>Logged in as :</strong> {{usr.email}} <!-- ← WRONG: 'usr' does not exist on scope --> </p>

The input was using:

ng-model="user.email"

but the output was using:

{{usr.email}}

Because ng-model wrote to user.email but the view displayed usr.email, the output remained blank no matter what was typed.

Before debugging (browser output):

Fig 1. Login page before debugging — "Logged in as" display is blank because {{usr.email}} has no value.

Chrome DevTools testing:

Fig 2. Chrome DevTools Console confirms: s.user.email = "prem@university.edu" but s.usr = undefined, causing a blank display.

After debugging:
<!-- login.html -- FIXED: both ng-model and display use the same variable --> <input type="email" ng-model="user.email" ... > <p> <strong>Logged in as :</strong> {{user.email}} <!-- ✓ CORRECT: now matches the ng-model variable --> </p>
After debugging (browser output):

Fig 3. Login page after debugging — "Logged in as" now correctly displays the typed email.

Undefined Variables:

In angular-app.js, the DashboardController reads the user session from AuthService.getSession(). If no session exists in localStorage (e.g., user navigated directly to the page without logging in), the variable session is null, and accessing session.name throws an error.

Before Debugging:
// angular-app.js — DashboardController (lines 661–673) app.controller('DashboardController', function($scope, AuthService, EquipmentService) { var session = AuthService.getSession(); $scope.currentUser = { name: session.name }; // ← ERROR if session is null! $scope.stats = { activeBookings: 3, pendingApprovals: 2, totalEquipment: EquipmentService.getAll().length, utilization: '68%' }; // Undefined variable — never initialized: console.log("Role:", $scope.userRole); // ← $scope.userRole was never set });
Before debugging (browser output):

Fig 4. Dashboard before debugging — page throws a TypeError because session is null, and $scope.userRole is undefined.

Chrome DevTools testing:

Fig 5. Chrome DevTools Console — localStorage.getItem('labtrack_session') returns null, confirming the root cause. s.userRole is also undefined.

After Debugging:
// angular-app.js — DashboardController — FIXED app.controller('DashboardController', function($scope, AuthService, EquipmentService) { var session = AuthService.getSession(); $scope.currentUser = { name: session ? session.name : 'Student' }; // ✓ null-safe $scope.userRole = session ? session.role : 'student'; // ✓ now initialized $scope.stats = { activeBookings: 3, pendingApprovals: 2, totalEquipment: EquipmentService.getAll().length, utilization: '68%' }; console.log("Name:", $scope.currentUser.name); // ✓ "Student" or real name console.log("Role:", $scope.userRole); // ✓ "student" or "admin" });
After debugging (browser output):

Fig 6. Dashboard after debugging — user name ("Prem Bose") and role ("student") now display correctly with the null-safe fix.

Controller Issue:

In equipment-catalog.html, the ng-controller attribute in the HTML must exactly match the controller name registered in angular-app.js. A single character difference causes AngularJS to throw an "argument is not a function" error and the entire page goes blank.

Before Debugging:
<!-- equipment-catalog.html --> <body ng-app="labTrackApp" ng-controller="catalogController"> ↑ lowercase 'c' — does not match the registered name!
/* angular-app.js — line 639 */ /* Controller is registered as: */ app.controller('CatalogController', function($scope, EquipmentService, AuthService) { ↑ uppercase 'C' — CatalogController
Before debugging (browser output):

Fig 7. Equipment Catalog before debugging — AngularJS throws [ng:areq] error and the page is blank because catalogController ≠ CatalogController.

Chrome DevTools testing:

Fig 8. Chrome DevTools Console — AngularJS is case-sensitive. The registered name is CatalogController (capital C) but the HTML says catalogController (lowercase c).

After Debugging:
<!-- equipment-catalog.html — FIXED --> <body ng-app="labTrackApp" ng-controller="CatalogController"> ↑ Uppercase 'C' — matches the registered name exactly!
/* angular-app.js — unchanged, correct as-is */ app.controller('CatalogController', function($scope, EquipmentService, AuthService) { $scope.searchQuery = ''; $scope.filters = { category: '', department: '', availability: '' }; $scope.equipmentList = EquipmentService.getAll(); // ✓ Now loads correctly ... });
After debugging (browser output):

Fig 9. Equipment Catalog after debugging — controller name fixed to CatalogController. All 6 equipment cards now load correctly from EquipmentService.
